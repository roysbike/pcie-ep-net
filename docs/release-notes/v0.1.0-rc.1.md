## Summary

First release candidate of **openmiop**: Ethernet (`omi0`) between the
Mixtile Blade 3 boards of a Mixtile Cluster Box over its internal PCIe
switch. Blade-to-blade frames are eDMA writes into the peer's PCIe BAR;
the payload never crosses the Cluster Box BMC. Protocol v4.

Release candidate: tested on one Cluster Box with four blades (details
below). See [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.1.0-rc.1/CHANGELOG.md).

## What's included

| Asset | Purpose |
| --- | --- |
| `openmiop-rc` | BMC helper, MIPS32 soft-float static binary for the MT7620A |
| `openmiop.init` | `/etc/init.d/openmiop` for OpenWrt on the BMC |
| `omi-peek` | BMC diagnostic: dumps an endpoint BAR header |
| `BUILD-INFO.txt` | commit, ref, CI run, compiler |
| `SHA256SUMS` | checksums of the files above |

Built by GitHub Actions from the tagged commit (see `BUILD-INFO.txt`).

* The **endpoint module** for Talos is inside the
  [mixtile-talos v0.1.0-rc.1](https://github.com/roysbike/mixtile-talos/releases/tag/v0.1.0-rc.1)
  image (system extension `openmiop`).
* The **BMC helper** is also packaged (`openmiop` package, started at
  boot) in the ClusterBox firmware
  [mixtile-clusterbox-mt7620a-openwrt v0.1.0-rc.1](https://github.com/roysbike/mixtile-clusterbox-mt7620a-openwrt/releases/tag/v0.1.0-rc.1).
  The binaries here are for Cluster Box firmware without that package.
* **Debian:** no prebuilt module (the Mixtile vendor kernel headers exist
  only in the Mixtile Debian image); build on the blade, see below.

## Supported hardware

* Mixtile Cluster Box (ASMedia ASM2824 switch, MT7620A BMC on OpenWrt 23.05 / 5.15)
* Mixtile Blade 3 (RK3588), link Gen3 x2 to the switch
* Blade OS: Debian 12 with the Mixtile vendor kernel 6.1.99, or Talos v1.14.2 via mixtile-talos

## Installation

### BMC (only without the v0.1.0-rc.1 ClusterBox firmware)

```sh
sha256sum -c SHA256SUMS
ssh <bmc> 'cat > /tmp/openmiop-rc' < openmiop-rc
ssh <bmc> 'cat > /tmp/openmiop.init' < openmiop.init
# as root on the BMC (prefix with sudo when logged in as a user):
ssh <bmc> 'cp /tmp/openmiop-rc /usr/bin/openmiop-rc && chmod 755 /usr/bin/openmiop-rc &&
  cp /tmp/openmiop.init /etc/init.d/openmiop && chmod 755 /etc/init.d/openmiop &&
  /etc/init.d/openmiop enable && /etc/init.d/openmiop start'
```

The BMC gets `omi0` = 10.20.0.1/24, MTU 9000.

### Debian blade (Mixtile vendor kernel 6.1.99)

```sh
sudo apt-get install -y build-essential git
git clone --branch v0.1.0-rc.1 https://github.com/roysbike/pcie-ep-net.git
cd pcie-ep-net
make -C drivers/openmiop KDIR=/usr/src/linux-headers-6.1-rockchip
sudo install -m 0644 drivers/openmiop/openmiop-ep.ko /usr/local/lib/openmiop-ep.ko
sudo install -m 0755 scripts/openmiop-ep-start.sh /usr/local/sbin/openmiop-ep-start
sudo install -m 0644 scripts/openmiop.service /etc/systemd/system/openmiop.service
echo 10.20.0.<last octet of the management address>/24 | sudo tee /etc/openmiop.addr
sudo systemctl daemon-reload && sudo systemctl enable --now openmiop
```

### Talos blade

See the [mixtile-talos v0.1.0-rc.1 release](https://github.com/roysbike/mixtile-talos/releases/tag/v0.1.0-rc.1).

## Upgrade

* BMC: replace `/usr/bin/openmiop-rc` (as above) and run
  `/etc/init.d/openmiop restart`; blades reconnect automatically.
* Debian: build and install the new module, then
  `sudo rmmod openmiop_ep && sudo systemctl restart openmiop`.
* All members must run protocol v4; v3 members are not activated.

## Verification

```sh
# blade
ip -d link show omi0                     # UP, LOWER_UP, mtu 9000
dmesg | grep openmiop                    # link up, node N, peer M up
ping -c3 10.20.0.1                       # BMC
ping -c3 -M do -s 8972 10.20.0.<peer>    # jumbo to another blade
# BMC
tail /tmp/openmiop-rc.log                # "node N active" per blade
```

## Tested configuration

One Cluster Box, four Blade 3 — blade160 and blade173 (Debian 12, vendor
6.1.99), two Talos v1.14.2 nodes (6.18.54-talos) — plus the BMC: five
members on one `omi0` segment. All endpoint links 8 GT/s x2, MTU 9000.
This exact helper source ran as a CI-built binary on the BMC with all
four endpoints; the driver source is identical to the tested build
`a7a8177`.

## Performance

| Path | Result |
| --- | --- |
| Debian ↔ Debian TCP, 1 stream | 8.0-8.3 Gbit/s each way, 0 retransmits |
| Debian ↔ Debian bidirectional | ~7.9 + 7.9 Gbit/s (10 min soak) |
| Debian → Talos / Talos → Debian | 6.4-6.6 / 7.4-7.5 Gbit/s |
| Talos ↔ Talos | 6.48 / 6.73 Gbit/s |
| SHA-256 transfers (512 MiB-1 GiB) | identical in every tested direction |
| BMC gateway | ~12 Mbit/s blade→BMC (management only) |

## Known limitations

* RX is polled; interrupt-driven RX is not implemented or tested.
* No multiqueue.
* Talos receives ~20 % slower than Debian (not investigated).
* TX polls the eDMA done bit (one core busy while sending).
* BMC root-port re-enumeration pauses fabric traffic ~1-2 s when a blade
  appears without a BAR address; a blade that disappears without the
  leave handshake can race a BMC read and wedge the fabric until the
  BMC reboots.
* Not tested: more than four blades, other slot orders, MPS other than
  128/256.
