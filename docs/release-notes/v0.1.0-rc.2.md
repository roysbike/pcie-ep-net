## Summary

openmiop **v0.1.0-rc.2**: Ethernet (`omi0`) between Mixtile Blade 3 boards
over the Mixtile Cluster Box PCIe fabric (OpenMIOP protocol v4).

* **Fix:** peers no longer stay "connecting" after the BMC re-enumerates
  the fabric and blade BAR addresses move (blades removed or added).
* **New:** `openmiop-dkms` package for Debian and Ubuntu.
* Release assets renamed to one scheme; no build leftovers.

Changes: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.1.0-rc.2/CHANGELOG.md).

## Installation

### Debian / Ubuntu

```sh
sha256sum -c --ignore-missing SHA256SUMS
sudo apt install ./openmiop-dkms_0.1.0-rc.2_all.deb
echo 10.20.0.<last octet of the management address>/24 | sudo tee /etc/openmiop.addr
sudo reboot
```

DKMS builds the module for the running kernel (headers required; the
Mixtile Debian 12 image's vendor headers are found automatically). The
package enables `openmiop.service` and disables Mixtile's
`load-miop.service` (both drive the same controller; reboot to switch).

### Cluster Box BMC without the ClusterBox firmware

```sh
tar xzf openmiop-0.1.0-rc.2-clusterbox-bmc-mipsel.tar.gz
cd openmiop-0.1.0-rc.2-clusterbox-bmc-mipsel
cat README.txt
```

## Upgrade

* Talos: upgrade to mixtile-talos v0.1.0-rc.2.
* Debian/Ubuntu from a manual rc.1 install: `sudo apt install ./openmiop-dkms_0.1.0-rc.2_all.deb`,
  remove `/usr/local/lib/openmiop-ep.ko` and the old
  `/etc/systemd/system/openmiop.service`, reboot.
* Mixed rc.1/rc.2 members speak the same protocol; the reconnect fix
  needs rc.2 on the blades.

## Verification

```sh
ip -d link show omi0                 # UP, mtu 9000
dmesg | grep openmiop                # node N, peer M up
ethtool -S omi0 | grep connect_renew # >0 only if a lost ack was recovered
ping -c3 -M do -s 8972 10.20.0.<peer>
```

## Tested

Cluster Box with four Blade 3, all Talos v1.14.2 on this driver
(mixtile-talos rc.2 test build), BMC on ClusterBox firmware rc.1:

* Upgrade of all four nodes one at a time: every node came back with all
  three peers up; etcd kept quorum.
* BAR moves on purpose: one blade shut down gracefully, BMC
  re-enumeration (the remaining three BARs moved down), blade powered on
  again (BMC re-enumerated, BARs moved back). Both times all 12 peer
  directions reconnected by themselves, without the rc.1 workaround.
* Jumbo ping (8972 bytes) from the BMC to all four blades.
* DKMS package: installed in Debian 12 (6.1.0-53-arm64), Debian 13
  (6.12.111+deb13-arm64), Ubuntu 22.04 HWE (6.8.0-138-generic) and
  Ubuntu 24.04 (6.8.0-146-generic) containers in CI; the module built for
  each kernel and was removed cleanly. Not booted on Debian/Ubuntu
  hardware in this release.

## Known limitations

* RX is polled; interrupt-driven RX is not implemented or tested. No multiqueue.
* Talos receives ~20 % slower than Debian (not investigated).
* A BMC re-enumeration pauses fabric traffic ~1-2 s when a blade appears
  without a BAR address. A blade that disappears without the leave
  handshake (crash, power loss) can still race a BMC read and wedge the
  fabric until the BMC reboots.
* The DKMS package is build-tested on the listed distribution kernels in
  CI; on hardware the driver ran on Talos 6.18.54 and on the Mixtile Debian
  12 vendor kernel 6.1.99 (rc.1). Those distributions' own kernels for
  Blade 3 need the PCIe endpoint device tree node.
