## Summary

openmiop **v0.2.0-rc.2**: the Cluster Box helper (`openmiop-rc`) no longer
takes the whole PCIe fabric down when one blade reboots, is reset or loses
power. The blade driver is unchanged from
[v0.2.0-rc.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.2.0-rc.1).

* **The problem.** The Cluster Box BMC (MT7620A) is the PCIe root complex.
  If `openmiop-rc` had a read of a blade's memory in flight while that
  blade's link dropped, the root complex stopped answering: every blade
  then needed a BMC reboot, and that reboot reset all their links.
* **The fix.** The helper takes each blade's link state from its switch
  port (Data Link Layer Link Active, answered by the switch itself) and
  sends nothing to a blade unless that link has been up for 1.5 s. After
  a blade announces it is leaving (normal reboot), and before `nodectl`
  resets a blade or cuts its power (release handshake), it leaves the
  blade alone until its link has dropped and come back.

Changes: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.2.0-rc.2/CHANGELOG.md).

## Installation (BMC, without the firmware update)

```sh
sha256sum -c --ignore-missing SHA256SUMS
tar xzf openmiop-0.2.0-rc.2-clusterbox-bmc-mipsel.tar.gz
scp -O openmiop-0.2.0-rc.2-clusterbox-bmc-mipsel/openmiop-rc root@<bmc>:/tmp/
ssh root@<bmc> 'cp /usr/bin/openmiop-rc /usr/bin/openmiop-rc.prev &&
  /etc/init.d/openmiop stop && cp /tmp/openmiop-rc /usr/bin/ && /etc/init.d/openmiop start'
```

Restarting the helper does not interrupt traffic between blades. Without
the matching `nodectl`, release a blade by hand before a hard reset:
`echo 1 > /var/run/openmiop-release.02:XX.0` (its switch port), and wait
until the file is gone.

## Verification

```sh
tail /tmp/openmiop-rc.log    # timestamped lines, "node N active" per blade
# on a blade reboot: "leaving", "detached", "link down at the switch port",
# then "BAR0 restored", "active" once its link is stable
```

## Tested

Lab Cluster Box: four Blade 3 on Talos v1.14.2 (driver v0.2.0-rc.1), this
helper installed by hand on the BMC.

| Test | Result |
| --- | --- |
| Normal blade reboots, helper running | 4 of 4: no outage, other blades untouched |
| Hard reset of a hung blade, released first (by hand, then by `nodectl reset`) | 2 of 2: root complex fine, blade back in ~30 s |
| Hard reset **without** a release | still stops the root complex (see below) |

## Known limitations

* A blade that loses power or crashes on its own, without a release, can
  still meet a read in flight and stop the root complex. Removing every
  read of blade memory from the BMC (push mode, a kernel module on the
  BMC) is in testing.
* A BMC reboot still resets the whole fabric (the MT7620A resets its PCIe
  core when it boots).
