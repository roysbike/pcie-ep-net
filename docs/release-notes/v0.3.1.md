## Summary

openmiop **v0.3.1** is a patch release for the Cluster Box side. The
`omi-rc` BMC module no longer shows a load average of 1.00 on an idle
Cluster Box. The blade driver is the same as in
[v0.3.0](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.3.0).

* **`omi-rc`: idle sleep in the control thread.** The thread paused
  1-2 ms between passes with `usleep_range()`, which sleeps
  uninterruptibly. The thread was in D state almost all the time, and
  Linux counts that in the load average. It now sleeps for the same time
  in `TASK_IDLE`. Timing and behaviour are unchanged.

Full list: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.3.1/CHANGELOG.md).

## Upgrade

Only the BMC: install ClusterBox firmware v0.1.1 (it reboots the BMC;
blades on v0.3 reconnect by themselves). Blades on 0.3.0 need nothing.

## Verification

```sh
# BMC
cat /proc/loadavg                       # ~0 on an idle BMC
ps w | grep '\[omi-rc\]'                # state IW, not DW
dmesg | grep omi0                       # "node N active" per blade
```

## Tested

Lab Cluster Box: four Blade 3 on Talos v1.14.2 with mixtile-talos
v0.3.0, BMC on firmware v0.1.0-rc.6 with this `omi-rc` loaded by hand.

| Test | Result |
| --- | --- |
| Module swap (`rmmod` old, `insmod` new) | all four blades active 1.7 s after `insmod`; `omi0` ping between all blades and to the BMC; blade DNS via the BMC |
| Load average | `[omi-rc]` in `IW` instead of `DW`; 1.08 → 0.27 within 2 min |
| `nodectl reset` of a blade | released, link down 28 ms later, active again 10.9 s after, node Ready in 57 s |
