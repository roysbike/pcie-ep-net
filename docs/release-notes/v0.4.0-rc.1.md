## Summary

openmiop **v0.4.0-rc.1** makes the Cluster Box gateway (LAN and internet
to the blades) about 1.5x faster. Until now the BMC wrote every frame
for a blade into the blade's BAR with its CPU, one uncached 32-bit PCIe
write per word: ~90-130 Mbit/s with the BMC CPU at 99 %. Now the blade
reads the frame from BMC memory with its own eDMA ("gateway pull"), and
the BMC writes only a 16-byte slot header.

* **Negotiated, protocol stays v4.** A blade with an eDMA read channel
  announces `OMI_HDR_GW_PULL`; `omi-rc` uses it only for such blades.
  Blades on v0.3.x keep working with the new `omi-rc`, and new blades
  with an old `omi-rc`.
* **Switches:** `openmiop-ep` parameter `gw_pull`, `omi-rc` parameter
  `pull` (both default on). Counters: `ethtool -S omi0 | grep gw_pull`.

Protocol details: [docs/push-mode.md](https://github.com/roysbike/pcie-ep-net/blob/v0.4.0-rc.1/docs/push-mode.md#gateway-pull-v04).
Changes: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.4.0-rc.1/CHANGELOG.md).

## Verification

```sh
# BMC
dmesg | grep omi0            # "node N active: ..., doorbell, gateway pull"
# blade
ethtool -S omi0 | grep gw_pull    # rx_gw_pulls grows, rx_gw_pull_errors 0
```

## Tested

Lab Cluster Box, 2026-10-13: BMC on firmware v0.1.1 with this `omi-rc`
loaded by hand; .108 on a mixtile-talos test image with this driver,
.133/.201/.204 on mixtile-talos v0.3.0. Same moment, .108 (pull) vs .133
(v0.3.0, MMIO):

| | gateway pull | v0.3.0 |
| --- | --- | --- |
| BMC -> blade, iperf3 on the BMC | 204 Mbit/s | 130 Mbit/s |
| LAN -> blade through the BMC (NAT, flow offloading) | 141-145 Mbit/s | 92-95 Mbit/s |
| Internet -> blade | 152-155 Mbit/s | 97-106 Mbit/s |
| Blade -> LAN | 264-272 Mbit/s | 267-276 Mbit/s |

444 158 frames pulled with 0 pull errors and 0 bad lengths. The BMC CPU
is now the limit (eth0 receive, NAT, the copy into the pull ring).

## Known limitations

- Only one blade ran the new driver at tag time; the roll to all four
  blades comes before v0.4.0.
- The BMC still copies each frame once into its ring (zero-copy is a
  later step).
- As in [v0.3.1](https://github.com/roysbike/pcie-ep-net/releases/tag/v0.3.1):
  `omi-rc` does not re-enumerate bridge windows; one flow uses one queue
  (~4.7 Gbit/s).
