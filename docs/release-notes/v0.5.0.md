## Summary

openmiop **v0.5.0** adds zero-copy to the Cluster Box gateway: LAN and
internet traffic to the blades is now ~40 % faster than in v0.4.0 and
~3x faster than in v0.3.

* **Gateway zero-copy.** With gateway pull (v0.4) the BMC still copied
  every frame from its own stack into a ring in its memory and cleaned
  the cache lines; the blade then read the copy. Now `omi-rc` hands the
  blade the bus address of the frame's buffer (skb) in the slot header,
  and the blade's eDMA reads it from there. The BMC frees the buffer once
  the blade has taken the slot. Broadcast, multicast and frames relayed
  between blades are still copied.
* **Negotiated.** A blade announces `OMI_HDR_GW_ZC`; `omi-rc` uses it
  only for such blades. v0.4.x and v0.3.x blades and BMCs keep working
  (copy path).
* **Switches:** blade module parameter `gw_zc`, `omi-rc` parameter `zc`
  (both default on). Counter: `ethtool -S omi0 | grep rx_gw_zc`.

Protocol details: [docs/push-mode.md](https://github.com/roysbike/pcie-ep-net/blob/v0.5.0/docs/push-mode.md#zero-copy-v05).
Changes: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.5.0/CHANGELOG.md).

## Verification

```sh
# BMC
dmesg | grep omi0                 # "node N active: ..., doorbell, gateway pull, zero-copy"
# blade
ethtool -S omi0 | grep -E 'rx_gw_zc|rx_gw_pull_errors'   # rx_gw_zc grows, errors 0
```

## Tested

Lab Cluster Box, 2026-10-13/14: .108 on a mixtile-talos test image with
this driver (openmiop 0.5.0-dev.1, same code), BMC on ClusterBox firmware
v0.2.0 with this `omi-rc` loaded by hand; .133 on v0.4.0 at the same
time (copy path).

| | v0.4.0 (copy) | v0.5.0 (zero-copy) |
| --- | --- | --- |
| LAN -> blade through the BMC (NAT, flow offloading) | 196-198 Mbit/s | 275-281 Mbit/s |
| BMC -> blade, iperf3 on the BMC | 192-193 Mbit/s | 275 Mbit/s |
| Blade -> LAN | 249-254 Mbit/s | 265-266 Mbit/s |

- SHA-256 of a 512 MB random file through the BMC: 3/3 identical; TCP
  checksum errors 0.
- `omi-rc` reloaded in the middle of a download (buffers the blade had
  not read yet were freed): the download finished with the right hash.
- Gateway stress (3 parallel 300 MB uploads + 300 MB download per
  round, BMC CPU 99 %): 16 rounds, gateway up, 0 stalls, 0 pull errors.
- 2.16 million zero-copy frames: BMC memory unchanged (no leak).
- v0.4.0 blades worked with this `omi-rc` at the same time (copy path).

## Known limitations

- The BMC CPU (one MIPS core) is still the limit: ~280 Mbit/s to a
  blade, ~250-270 Mbit/s from a blade.
- Zero-copy needs 32-bit bus addresses for the BMC's buffers (always true
  on the MT7620A); otherwise `omi-rc` falls back to the copy.
- A BMC reboot drops every blade link for the length of its boot; with
  DRBD 9.3.4 check `out-of-sync:` 0 first
  ([LINBIT/drbd#153](https://github.com/LINBIT/drbd/issues/153)).
- When a blade reconnects, `omi-rc` may log two harmless `resync`
  warnings.
