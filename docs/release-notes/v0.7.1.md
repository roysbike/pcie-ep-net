## Summary

openmiop **v0.7.1** is a fix release. The blade driver `openmiop-ep`,
wire format, BAR layout and handshake are unchanged (protocol v4);
v0.7.1 blades work with v0.7.0 and v0.6 blades.

* **blade3-nvme-recover: NVMe link drops shorter than `poll_ms`.** On
  2026-10-31 the M.2 NVMe of a blade dropped its link by itself (no
  Cluster Box reset) and was back at 2.5 GT/s within the 20 ms poll. The
  module did not see it, but the Root Port had lost its bus numbers and
  Memory/Bus Master enable and the NVMe its BARs: nvme marked the
  controller dead, the ZFS pool on it was suspended and the node needed a
  hard reset. The module now also treats a Root Port without its
  secondary bus number or Memory enable as a link down and runs the usual
  recovery (restore the Root Port and NVMe config, raise the speed, reset
  the NVMe). New read-only parameter `unseen`, dmesg
  `link went down unseen (Root Port reset), recovering`.
* **omi-rc: fan-in load no longer wedges the BMC side of the fabric.**
  Completion Timeout Disable on the root port above the switch (parameter
  `ct_off`, default on) and a link-loss debounce for the switch ports
  (`link_down_ms`, default 100). Already shipped in ClusterBox firmware
  v0.4.3; released here as source and in the BMC helper tarball.

Changes: [CHANGELOG.md](https://github.com/roysbike/pcie-ep-net/blob/v0.7.1/CHANGELOG.md).

## Tested

Lab Cluster Box, Talos v1.14.4, mixtile-talos test image with this
blade3-nvme-recover:

* With `poll_ms` raised to 3000, a short Link Disable pulse on the NVMe
  Root Port (the drop the module could not see before): dmesg
  `link went down unseen`, link up after ~6 s, NVMe reset, back `live`
  at 8 GT/s. No I/O or ZFS errors, the pool stayed ONLINE, DRBD and the
  PostgreSQL clusters on the node stayed healthy.
* omi-rc (firmware v0.4.3): 3 blades sending into one (13.3 Gbit/s) for
  30 and 60 s with gateway pings and `nodectl` polling: no wedge, no
  blade dropped. A 24 h soak of two bidirectional blade pairs
  (~7.5 Gbit/s per direction) afterwards: etcd 3/3 throughout, driver
  error counters unchanged.
