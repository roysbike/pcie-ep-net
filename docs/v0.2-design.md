# openmiop v0.2: interrupts, multiqueue, offloads (design draft)

Status: draft on `claude/v0.2-multiqueue`. Numbers marked *measured* come
from Talos blades in the Cluster Box; everything else is a plan.

## Where v0.1 spends CPU (measured, 2026-10-07, .108, MTU 9000, one TCP stream)

| | throughput | CPU busy (8 cores) |
|---|---|---|
| TX .108 → .133 | 2.57 Gbit/s | 38 % |
| RX .133 → .108 | 3.17 Gbit/s | 32 % |

- No interrupt is used. RX: the `omi-ctl` kthread polls the rings every
  20-50 us and runs NAPI from its own context (`local_bh_enable()`), so
  all RX processing happens wherever the scheduler put that thread, often
  on the A55 cores 0-3. TX: `omi-tx` busy-waits on the eDMA done bit.
- One NAPI, one TX queue, one eDMA channel.
- No TX checksum offload (`tx-checksumming: off [fixed]`): TCP checksums
  every byte on the CPU (`do_csum`, `csum_and_copy`). No TSO: the stack
  segments to MTU before the driver.
- RX copies every frame out of the BAR ring (`memcpy`) after a cache
  invalidate (non-coherent DMA).

## Hardware available (RK3588 PCIe3 x4 controller in EP mode)

- eDMA with its own interrupt lines `dma0..dma3` in the DT (to be
  confirmed per channel by experiment 1).
- GICv3 with MBI (`mbi-ranges = <424 56>`) and an MBI alias frame at
  `0xfe610000`: a separate 64 KiB page that only contains SETSPI. A write
  of an SPI number there raises that SPI. Linux exposes it as an MSI
  parent (`MBI-` domain), so a driver can allocate vectors with
  `platform_device_msi_init_and_alloc_irqs()` and get normal IRQs with
  affinity.
- Inbound iATU address-match regions: a 64 KiB window of BAR0 can be
  redirected from DRAM to that alias frame. A peer's eDMA writing one
  word there becomes an interrupt on the receiver: an RX doorbell, like
  an MSI-X vector on a NIC.

## Target design (protocol v5, negotiated per peer)

1. **RX queues and RSS.** The receiver splits the per-sender ring area
   (2.5 MiB today) into up to 4 queues. The sender picks the queue from
   the flow hash (`skb_get_hash()`), so one flow stays in order and
   different flows land on different queues. Each queue has its own
   NAPI and its own MBI vector; vectors get affinity hints spread over
   the A76 cores (ethtool `-l`/`-x` style controls later).
2. **RX doorbell.** After the head write, the sender's eDMA list writes
   the queue's vector number into the receiver's doorbell window. The
   receiver handler masks the vector and schedules NAPI; NAPI unmasks
   when the ring is empty. While NAPI runs, doorbells only set pending
   bits: interrupt rate is bounded like on a NIC with masking. A slow
   watchdog poll (hundreds of µs) covers a doorbell that overtakes its
   data or arrives while the window moves after a BAR re-enumeration.
3. **TX completion interrupt.** eDMA done/abort interrupts replace the
   busy wait. `ndo_start_xmit` builds and starts a run when the channel
   is idle; the done interrupt retires it and starts the next one with
   everything that queued meanwhile (same batching as v0.1, no polling
   thread).
4. **TX queues.** One netdev TX queue per eDMA write channel (up to 4),
   each with its own linked lists and scratch, XPS by CPU.
5. **Offloads with virtio-net semantics.** Slot header carries
   `NEEDS_CSUM` + `csum_start/csum_offset`, and GSO type/size. TX
   advertises `NETIF_F_HW_CSUM` and TSO/GSO; the receiver hands the
   frame to the stack as `CHECKSUM_PARTIAL` (and as a GSO skb), so
   checksums are only computed if the frame leaves through a device that
   needs them. Frames to v4 peers and to the gateway get the checksum
   computed in software (`skb_checksum_help()`) and are segmented.
6. **Variable-size records.** Byte-addressed rings with 64-byte aligned
   records instead of fixed 10 KiB slots, so small frames (TCP ACKs) do
   not take 10 KiB and 64 KiB GSO frames fit.
7. **Compatibility.** The BAR header, control line, peer table and
   gateway rings stay v4: the BMC helper does not change. v5 is
   negotiated per peer: the sender announces v5 in its producer line
   with its connect token; a v5 receiver acknowledges with its queue
   geometry and doorbell data in the credit line. A v4 peer never writes
   those fields, so the pair falls back to v4 framing.

## Experiments (on .108 only)

1. `experiments/omi-dbtest`: eDMA channel count, which `dmaN` line fires
   for a write channel, MBI vector allocation, doorbell window via
   address-match iATU region, BMC write into the window raises the
   vector, DRAM unaffected. Also: priority of the address-match region
   over the BAR-match region 0.
2. Driver with TX done interrupt (v4 wire format): CPU and throughput vs
   v0.1.
3. Two v5 nodes (needs a second node: done only with an image already
   tested on .108, upgraded one node at a time).

## Test plan before a release

Ring and full-mesh iperf3 (1 and 8 streams), SHA-256 file transfers,
BAR moves (forced re-enumeration), blade reload, mixed v4/v5 peers,
soak (≥ 1 h bidirectional), CPU per Gbit/s compared with v0.1.
